## 1. Why Firebase exists

This skill covers the problem Firebase solves and the mental model behind it. If you only remember this skill, you should still not misuse the platform.

### The pain

You have built a model or a small tool, and a handful of people want to use it from their phones. You can train the model. You have never run a login system, a database that thousands of phones talk to, a push service, or a crash reporter.

You write the obvious thing: a FastAPI service with a users table. Then the list grows: password reset emails, social login, sessions that expire, a database exposed to the internet, notifications when a job finishes, file uploads, and a way to see why the app crashes on one phone. Each piece is a week of unglamorous work that is not your product, and each is a place to leak user data if you get it wrong.

### The core idea

**Firebase is a catalogue of separable managed services under one project.** Google runs and scales them, and the app calls them through ready-made SDKs.

Its signature move is that **the client talks to the services directly**. There is often no server of yours between the phone and the database. A small policy language called security rules decides what each signed-in user may touch.

```
 Classic                               Firebase (direct-to-service)
 ───────                               ────────────────────────────
 App ─► Your API ─► Your DB            App ─► Auth       (who are you?)
        (you write auth,                App ─► Firestore  (reads/writes, checked by rules)
         validation, scaling)           App ─► Storage / Functions / FCM ...
                                        (Google runs and scales them)
```

### What you trade

- You gain speed: no backend to build or run for the chores.
- You give up control and portability. You accept Google's data model, limits, pricing and roadmap.
- Your entire authorization layer moves into a rules file.

### Three facts to hold on to

1. Services are **separable**, so adopt only what you need.
2. With direct access, **the rules are your security**.
3. Every product has a billing model, and the database bills per operation, so usage patterns become cost.
