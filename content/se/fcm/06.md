## 6. Functions & Hosting

After this skill you can decide when the Notes app needs server code, write and test a Cloud Function that runs when a note is created, put the web app online with Firebase Hosting, and let people attach a photo to a note with Cloud Storage.

### Cloud Functions and when you need one

**Cloud Functions** are small pieces of your own code that Google runs for you when something happens: a web request, a change in Firestore, or a time of day. You do not rent or manage a server. This style is called **serverless** (you write the code, the platform runs and scales it).

Most of the Notes app needs no function at all. The client can create, read and delete notes directly, and security rules protect them. Adding a function adds code to deploy, logs to watch and a bill to pay. So use one only when the client cannot be trusted or cannot do the job:

| Task | Where |
|---|---|
| Save or list my notes | Client |
| Keep a count users cannot fake | Function |
| Use a secret API key | Function |
| Send push to another user | Function |
| Run every morning | Function |

The rule of thumb: if the logic needs a secret, needs to be trusted, or must run when no app is open, it belongs in a function. Functions use the **Admin SDK**, which bypasses security rules (see Security rules), so the function code must do its own checks.

You can write functions in JavaScript, TypeScript or Python. The examples here use JavaScript on Node.js.

### Three kinds of trigger

A **trigger** is the event that starts a function. The three you will use most:

**HTTPS**: runs when someone calls a URL.

```js
const {onRequest} = require(
  "firebase-functions/https");

exports.hello = onRequest(
  (req, res) => {
    res.send("Hello from Notes");
  });
```

There is also `onCall`, an HTTPS function that receives the caller's sign-in for you. It is the easiest choice when your own app is the only caller.

**Firestore**: runs when a document is created, updated or deleted. The next section shows one.

**Scheduled**: runs on a timetable, using Cloud Scheduler.

```js
const {onSchedule} = require(
  "firebase-functions/scheduler");

exports.daily = onSchedule(
  "every day 09:00",
  async () => {
    // for example, send reminders
  });
```

Each scheduled job has a small monthly fee after a few free jobs per account; check the pricing page. The daily reminder itself is built in Sending push.

### Worked example: count notes on create

The Notes app shows "You have 12 notes". If the client kept that number, anyone could set it to a million. A function keeps it honest. It runs when a note is created and increases `noteCount` on `users/{uid}`.

Run `firebase init functions` in your project folder and choose JavaScript. Then put this in `functions/index.js`:

```js
const {logger} = require(
  "firebase-functions");
const {onDocumentCreated} = require(
  "firebase-functions/firestore");
const {initializeApp} = require(
  "firebase-admin/app");
const {getFirestore, FieldValue} =
  require("firebase-admin/firestore");

initializeApp();
```

```js
exports.onNote = onDocumentCreated(
  "notes/{noteId}",
  async (event) => {
    if (!event.data) return;
    const note = event.data.data();
    logger.info("New note",
      event.params.noteId);
    await getFirestore()
      .doc(`users/${note.ownerId}`)
      .set({
        noteCount:
          FieldValue.increment(1),
      }, { merge: true });
  });
```

`event.data` is the new document. `event.params.noteId` is the wildcard value. Also update your rules so clients cannot write `noteCount` themselves.

One honest limit: event triggers can, rarely, run more than once for the same event. A count may drift by one. If exactness matters, store which note ids were counted, or recount on a schedule.

Deploy and read logs:

```bash
firebase deploy --only functions
firebase functions:log
```

`logger.info` lines appear in those logs and in the Google Cloud console logs.

### Cold starts, plans and secrets

**Cold start.** When a function has not run for a while, Google must start a fresh copy before your code runs. The first request is slower, often by a second or more. Later requests reuse the warm copy. You can set `minInstances: 1` in the function options to keep one copy ready, but you pay for that copy even when idle. For a note counter, a slow first run does not matter. For a checkout button, it might.

**Plan.** The Emulator Suite runs functions on any plan, for free, on your computer. To **deploy** functions, the project must be on the **Blaze** plan (pay as you go, with a no-cost usage level each month). Set a budget alert first; see Costs & safety.

**Secrets.** Never put an API key in your code or in the client. Store it in Google Cloud **Secret Manager** (an encrypted store for secrets) with the CLI:

```bash
firebase functions:secrets:set \
  MAIL_API_KEY
```

Then give only the functions that need it access:

```js
const {defineSecret} = require(
  "firebase-functions/params");
const mailKey =
  defineSecret("MAIL_API_KEY");

exports.mail = onRequest(
  { secrets: [mailKey] },
  (req, res) => {
    const key = mailKey.value();
    // call the mail service here
    res.send("ok");
  });
```

After changing a secret, redeploy the functions that use it. In the emulator, a `.secret.local` file can hold test values.

### Firebase Hosting

**Firebase Hosting** puts your built web app (HTML, JavaScript, CSS, images) online over HTTPS. Files are served from a **CDN** (servers in many countries that keep copies close to users). Hosting works on the free Spark plan within a no-cost quota.

Build your app first (for example `npm run build`, which often creates a `dist` folder). Then in `firebase.json`:

```json
{
  "hosting": {
    "public": "dist",
    "ignore": ["firebase.json",
      "**/.*",
      "**/node_modules/**"],
    "rewrites": [{
      "source": "**",
      "destination": "/index.html"
    }]
  }
}
```

A **rewrite** tells Hosting which file to serve for a path. The one above sends every path to `index.html`, which single-page apps need so that a reload on `/notes/n1` does not show "Not found". A rewrite can also send a path such as `/api/**` to a Cloud Function.

Deploy to the live site:

```bash
firebase deploy --only hosting
```

Before that, you can share a test copy on a **preview channel** (a temporary URL separate from the live site):

```bash
firebase hosting:channel:deploy \
  photo-feature --expires 3d
```

A preview channel expires after 7 days by default, and at most 30 days.

### Photos with Cloud Storage

**Cloud Storage for Firebase** stores files such as photos. Firestore is for small structured data; a photo goes in Storage, and the note keeps only its path.

Plan note: Cloud Storage for Firebase now needs the **Blaze** plan, even for the default bucket. Blaze includes a no-cost usage level. The Storage emulator works on any plan.

Upload from the web client with the modular SDK:

```js
import { getStorage, ref,
  uploadBytes } from
  "firebase/storage";
import { doc, updateDoc } from
  "firebase/firestore";

const storage = getStorage();

async function attachPhoto(id, file) {
  const uid = auth.currentUser.uid;
  const path =
    `photos/${uid}/${id}.jpg`;
  await uploadBytes(
    ref(storage, path), file,
    { contentType: "image/jpeg" });
  await updateDoc(
    doc(db, "notes", id),
    { photoPath: path });
}
```

To show the photo, call `getDownloadURL(ref(storage, path))` and use the URL in an `<img>`. Store the **path**, not the URL. A download URL carries a token, and anyone who has the URL can open the file, whatever your rules say. If the photo is private, do not share or save its URL.

The rules that allow only the owner to upload images under 5 MB are in Security rules.

### Common mistakes

- **Writing a function for plain CRUD.** You see slower saves and extra cost. Fix: let the client write directly and protect it with rules.
- **Deploying on Spark.** The functions deploy fails and asks you to upgrade. Fix: test in the emulator, or move to Blaze with a budget alert.
- **Keys in code.** A secret ends up in your repository or browser. Fix: use `functions:secrets:set` and `defineSecret`.
- **Saving the download URL as access control.** A private photo becomes viewable by anyone with the link. Fix: save `photoPath` and fetch the URL only when showing it.
- **No SPA rewrite.** Reloading a deep link shows "Not found". Fix: rewrite `**` to `/index.html`.
