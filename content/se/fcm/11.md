## 11. Functions & Hosting

This skill covers the parts of Firebase that run code and serve files: Cloud Functions, Hosting and Cloud Storage.

### Cloud Functions

Serverless code (Node.js or Python) that runs on a trigger: an HTTP request, a new Firestore document, a new user, or a schedule. This is where **trusted logic** lives, because client code can be tampered with.

Costs and limits:
- It **requires the Blaze plan**. [checked 2026-11-23]
- **Cold starts**: the first call after idle is slower.
- It bills per invocation, and debugging happens in a remote environment.
- If you already run a backend, you may not need it at all.

### Hosting

Fast static hosting on a CDN with free HTTPS, plus rewrites that can route paths to a function or a container. Lock-in is **low**: it serves files, and you can move them anywhere. A newer **App Hosting** targets server-rendered web frameworks. [fast-moving]

For LevelUp this is already covered by Caddy on the droplet.

### Cloud Storage for Firebase

User-uploaded files (images, audio, PDFs) in a Google Cloud Storage bucket, protected by its own rules language and the signed-in identity. Use it for blobs, never as a database.

Plan requirements for storage have changed before. One check on the day this track was written said it is available on Spark within a quota, but confirm at project creation. [fast-moving, unsure]

### Where trusted logic lives

The client is untrusted: users can edit their own score, role or balance if rules allow it. Put authoritative values behind a Cloud Function, or behind your own backend using the Admin SDK, and have the rules forbid client writes to those fields.

| Job | Good place |
|---|---|
| Show data to its owner | Client plus rules |
| Award points, change a role | Function or your backend |
| Send a push | Your server or a function |
| Serve the web app | Hosting |
