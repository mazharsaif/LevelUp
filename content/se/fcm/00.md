## How to read this track

This track gives you judgment about Firebase: what the products are, which ones to adopt, which to avoid, and what each costs you. It follows the learning guide `learning-guides/firebase.md`, and it goes deepest on the things that hurt people: security rules, billing and lock-in.

The running example is LevelUp. It already has its own FastAPI backend and accounts, so the question is always "what does Firebase add that I do not already have?" The answer, for LevelUp, turns out to be push notifications and not much else.

### The big picture in five lines

1. **Firebase** is Google's catalogue of managed app services: sign-in, a database, file storage, functions, hosting, push, analytics and crash reports. You can adopt one and ignore the rest.
2. The app usually talks to these services **directly**, so **security rules** are your authorization layer, not an afterthought.
3. The database bills **per operation**, so how you read data becomes your cost.
4. Some pieces are easy to leave (push, hosting) and some are not (Firestore, Authentication). Adopt the leaves freely and think hard before adopting the roots.
5. If you already have a backend, take only what it lacks.

### Tags you will see

- **[consensus]** widely agreed
- **[depends]** contested, or depends on context
- **[fast-moving]** changes quickly, so verify before relying on it
- **[unsure]** not confident

Plan and quota facts were checked against Google's docs on 2026-11-23. Treat every number as a snapshot.

### Order

Start with why Firebase exists and the product map. Then sign-in and the database, then security rules (they need both). After that branch into push (tokens, then sending) and serverless and measurement. Finish with the two judgment skills, use it or not and pitfalls, and the final review.
