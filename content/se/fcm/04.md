## 4. Sending a push

This skill covers how your server sends a message, and the choices that decide whether your code runs when the app is closed.

### HTTP v1 and a service account

Your server authenticates with a Google **service-account key** (a JSON file) and calls the **HTTP v1** API, directly or through the `firebase-admin` SDK. The older "legacy" server-key API has been shut down [fast-moving].

```python
# pip install firebase-admin   (needs a real service-account key)
import datetime
import firebase_admin
from firebase_admin import credentials, messaging

firebase_admin.initialize_app(credentials.Certificate("service-account.json"))

def ring(token: str, from_name: str, gate_id: str) -> str:
    msg = messaging.Message(
        token=token,
        data={"type": "nudge", "from": from_name, "gate": gate_id},  # values must be strings
        android=messaging.AndroidConfig(priority="high", ttl=datetime.timedelta(minutes=2)),
    )
    return messaging.send(msg)  # message id on success, raises on failure
```

Heads-up [fast-moving]: with `firebase-admin` 7.8.0 a `DeprecationWarning` said `Message.token` is deprecated in favour of `Message.fid` (a Firebase installation ID). A message was only constructed, not sent, so read the current SDK docs before wiring it in.

### Data versus notification messages

This is the most important distinction in FCM.

| Type | Who shows it | When your code runs | Use it for |
|---|---|---|---|
| Notification message | The OS tray, automatically | Only if the app is in the foreground | Simple "you have news" banners |
| Data message | Nobody; your app decides | Always, even in the background, for a short window | Custom UI, ringing, silent sync |

A data message gives you control and costs a little code. A notification message is zero code, but you lose control while the app is backgrounded. [consensus]

### Priority and TTL

- **High priority** can wake a phone in Doze (battery-saving idle) and is what you want for "ring now". **Normal** priority is batched to save power.
- Android may demote repeated high-priority messages that never produce something the user sees. Use it sparingly. [consensus]
- **TTL** (time to live) is how long FCM keeps trying. A stale "ring" is useless, so set minutes, not the default of up to four weeks. [fast-moving]

### Payload size and topics

- A message is limited to about 4 KB [rule of thumb, verify in the current docs]. Send an id and a short label, and let the app fetch details from your server. Never send secrets.
- **Topics** let you send once to a named group ("everyone in party 7") and FCM fans out. That is convenient for broadcasts, but you lose per-user control. For a small app, sending per token from your own table is simpler and safer. [depends]
