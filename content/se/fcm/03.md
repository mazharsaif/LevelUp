## 3. Tokens and your users

This skill covers how FCM knows which phone to reach, and why your users never sign in with Google.

### The registration token

A **registration token** is an opaque string that identifies *one app install on one device*. The app asks the Firebase SDK for it and uploads it to your server along with the logged-in user id. [consensus]

It is **not a user id**:
- one user can have several tokens (phone, tablet);
- a token can change (reinstall, restore to a new phone, cleared data, long inactivity).

### Your server holds the mapping

Firebase never learns your usernames. You keep a table `user → tokens`:
- **add** a token on login, and whenever the SDK reports a new one;
- **delete** it on logout.

This is also why the user does **not** need a Google login. The token comes from the Firebase config baked into your app build, not from a signed-in Google account. [consensus] On modern Android the phone does need Google Play Services. Whether a phone with no Google account signed in receives pushes is worth confirming on a test device; this track did not test it.

### Stale tokens are normal

FCM tells you when a token is dead: the send fails with `UNREGISTERED` (`UnregisteredError` in the Python SDK). Delete that token, or your fan-out slows down and your logs fill up forever.

```python
import datetime, sqlite3
from firebase_admin import messaging

db = sqlite3.connect("tokens.db")
db.execute("create table if not exists tokens(user text, token text primary key)")

def send_to_user(user: str, data: dict[str, str]) -> None:
    for (tok,) in db.execute("select token from tokens where user=?", (user,)).fetchall():
        try:
            messaging.send(messaging.Message(token=tok, data=data, android=messaging.AndroidConfig(
                priority="high", ttl=datetime.timedelta(minutes=2))))
        except messaging.UnregisteredError:
            db.execute("delete from tokens where token=?", (tok,)); db.commit()
```

This was run with `messaging.send` mocked: the dead token is removed and the good one stays.

### Android 13 and the notification permission

From Android 13 the app must ask for the `POST_NOTIFICATIONS` permission. With no permission there is no visible notification, however well FCM delivered the message. LevelUp's native app already has an `askNotifications` bridge for this.
