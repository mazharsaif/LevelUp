## 2. AI and ML fundamentals

This skill covers AIF-C01 Domain 1 (20% of the exam): the vocabulary, the main kinds of learning, the ML lifecycle and which AWS service fits which problem.

### AI, ML, deep learning, generative AI

- **Artificial intelligence (AI)**: any technique that lets a computer do something we would call intelligent.
- **Machine learning (ML)**: a subset of AI where the system learns patterns from data instead of following hand-written rules.
- **Deep learning**: ML with neural networks of many layers. It is strong on images, audio and text, and needs more data and compute.
- **Generative AI**: deep-learning models that *create* new content (text, images, code) rather than only predicting a label.

A **model** is the learned function. **Training** fits it to data. **Inference** is using the trained model to make predictions on new data.

### Kinds of learning

| Type | Data | Example tasks |
|---|---|---|
| Supervised | Labelled examples (input → correct answer) | Classification (spam or not), regression (house price) |
| Unsupervised | No labels | Clustering customers, anomaly detection, dimensionality reduction |
| Reinforcement | Rewards from an environment | Robots, game playing, ad bidding |
| Self-supervised | Labels created from the data itself | Pre-training large language models (predict the next word) |

**Classification** predicts a category. **Regression** predicts a number. **Clustering** groups similar items without labels.

### The ML lifecycle

1. Define the business problem and the success metric. Ask whether ML is needed at all.
2. Collect data, then clean it and explore it.
3. Engineer features: turn raw data into useful model inputs.
4. Train and tune the model.
5. Evaluate it on data it has never seen.
6. Deploy it for real-time or batch predictions.
7. Monitor it for drift, and retrain when quality drops.

ML is a poor fit when you need exact, explainable rules (tax calculations), when there is little or no data, or when a simple rule already works.

### Fitting: bias, variance, overfitting

- **Overfitting**: great on training data, poor on new data. The model memorised noise. Fixes: more data, regularisation, a simpler model, early stopping, dropout.
- **Underfitting**: poor on both. The model is too simple. Fixes: more features, a more complex model, longer training.
- **Bias** is error from wrong assumptions (it leads to underfitting); **variance** is sensitivity to the particular training data (it leads to overfitting).

Always split your data into **training**, **validation** (for tuning) and **test** (a final, untouched check) sets. **Data leakage** happens when information from the test set or the future leaks into training, giving falsely good results.

### Choosing AWS services

| Need | Service |
|---|---|
| Text from scanned documents and forms | Amazon Textract |
| Sentiment, entities, PII in text | Amazon Comprehend (Comprehend Medical for health text) |
| Objects, faces, moderation in images and video | Amazon Rekognition |
| Speech to text | Amazon Transcribe |
| Text to speech | Amazon Polly |
| Translation | Amazon Translate |
| Chatbots with intents | Amazon Lex |
| Recommendations | Amazon Personalize |
| Generative AI with foundation models | Amazon Bedrock |
| Build, train and deploy your own models | Amazon SageMaker AI |

Rule of thumb for the exam: a managed AI service beats a custom model when the task is common and you want the "least operational overhead".

### Self-check

1. A model scores 99% on training and 70% on validation. What is happening and what is one fix?
2. Which learning type groups customers with no labels?
3. Which service extracts tables from scanned invoices?
4. Name two situations where ML is the wrong tool.

**Answers.** 1: Overfitting. Fix it with regularisation, more data, a simpler model or early stopping. 2: Unsupervised learning (clustering). 3: Amazon Textract. 4: When exact rules are required and already known, or when there is not enough data. Lab: supervised regression; unsupervised clustering; supervised classification; reinforcement; generation with an FM; unsupervised anomaly detection.
