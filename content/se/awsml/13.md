## 13. Monitoring, cost and security

This skill covers MLA-C02 Domain 4 (24%): watching models in production, keeping infrastructure and token costs under control, and securing ML and AI workloads end to end.

### SageMaker Model Monitor

Model Monitor compares live traffic, captured with **data capture** on the endpoint, with a **baseline** created from the training data. It runs on a schedule and writes violations and CloudWatch metrics.

| Monitor | Detects | Needs |
|---|---|---|
| Data quality | Input drift: changed distributions, missing values, new categories | Baseline statistics and constraints |
| Model quality | Accuracy, precision, RMSE and so on dropping | Ground-truth labels merged in later |
| Bias drift | Changes in bias metrics across groups | Clarify configuration |
| Feature attribution drift | Changes in which features drive predictions (SHAP) | Clarify configuration |

When a violation shows up, a CloudWatch alarm can notify you or trigger retraining (skill 12).

### Observability

- **Amazon CloudWatch**: endpoint metrics (`Invocations`, `ModelLatency`, `OverheadLatency`, `Invocation4XXErrors`, `Invocation5XXErrors`, CPU, GPU and memory), logs, alarms and dashboards.
- **Bedrock metrics**: `Invocations`, `InvocationLatency`, `InputTokenCount`, `OutputTokenCount` and throttles per model. **Model invocation logging** stores prompts and responses in CloudWatch Logs or S3.
- **CloudWatch generative AI observability**: dashboards and traces for model calls, agents, tool calls and knowledge-base retrievals.
- **Amazon Bedrock AgentCore Observability** and **AWS X-Ray**: trace agent steps and requests across services, to find slow or failing tool calls, coordination failures and truncated streaming responses.
- **A/B tests** with production variants compare models on live metrics. **Bedrock evaluations** can run regularly against fresh samples of production prompts.

### Cost: infrastructure

| Lever | What to do |
|---|---|
| Instance family | CPU (c, m, Graviton c7g / m7g) for small models; GPU (g5, g6, p4, p5) for deep learning; AWS Inferentia (inf2) for cheap inference and Trainium (trn1) for cheap training |
| Right-sizing | Use SageMaker Inference Recommender and AWS Compute Optimizer |
| Purchase option | On-demand for spiky load; SageMaker Savings Plans for steady use (up to about 64% off); spot for training (up to 90% off) |
| Scale | Auto scaling; serverless or asynchronous endpoints that scale to zero; stop idle Studio apps |
| Budgets | AWS Budgets with alerts and actions, Cost Explorer by tag, Cost Anomaly Detection, service quotas as hard limits on resources |

### Cost: foundation models

- You pay for **tokens in and out**. Shorten prompts, cap `maxTokens`, and ask for concise formats.
- Use the **smallest model** that passes your evaluation, and route only hard requests to a big model.
- **Prompt caching** reuses a long, repeated prefix (system prompt or documents) at a lower price.
- **Batch inference** is cheaper for offline jobs. **Provisioned throughput** pays off only for steady, high use.
- **RAG costs**: embedding all your documents again when you re-index, the vector store's storage and any minimum capacity, and the extra prompt tokens from retrieved chunks. Retrieve fewer, better chunks with reranking.
- **Agent costs**: each reasoning step and tool call is another model call. Watch the steps per task and cap the iterations.

### Security: identity and data

- **Least privilege**: SageMaker **execution roles** scoped to specific buckets and prefixes; app roles that allow only `sagemaker:InvokeEndpoint` on one endpoint ARN or `bedrock:InvokeModel` on specific model ARNs. Use condition keys and **SageMaker Role Manager** to start.
- **Encryption**: KMS keys for S3, training volumes (`volume_kms_key`), model artefacts, endpoints, Feature Store and knowledge bases. TLS in transit, enforced with an `aws:SecureTransport` bucket policy. Inter-container traffic encryption for distributed training.
- **Secrets** in AWS Secrets Manager, never in code or notebooks.
- **Credentials for foundation models**: IAM role credentials for apps on AWS. **Bedrock API keys** are for quick access: short-term keys (session-based, up to 12 hours) are preferred; long-term keys are tied to an IAM user and should be limited and rotated.
- **Bedrock Guardrails** for content filters, denied topics, PII masking, prompt-attack filters and contextual grounding checks, applied to models, agents and knowledge bases.

### Security: network, audit and supply chain

- **VPC isolation**: training jobs, processing jobs, endpoints and Studio in private subnets with security groups. Use VPC endpoints (PrivateLink) for SageMaker API and runtime, Bedrock, S3 and ECR. **Network isolation mode** blocks all outbound calls from the training container.
- **Audit**: **CloudTrail** records who called which API (management events by default; data events optionally). **AWS Config** tracks configuration and flags non-compliant resources. **Amazon Macie** finds PII in S3.
- **Supply chain**: **Amazon Inspector** scans ECR images and Lambda functions for vulnerabilities; **Amazon CodeGuru Security** scans code in CI/CD; pin dependencies and use trusted base images.
- **Troubleshooting `AccessDenied`**: read the error (which action on which resource), check the role's policy, the resource policy (bucket or KMS key), the VPC endpoint policy and any service control policy, and find the failed call in CloudTrail.

### Lab: monitor, tune cost, lock down (about $0.70)

1. Deploy the XGBoost model to a real-time endpoint with 100% data capture. Create a baseline with `DefaultModelMonitor.suggest_baseline()`, send 300 normal rows and 300 shifted rows (`age + 20`, `balance × 3`), run a monitoring job and read `constraint_violations.json`. Delete everything.
2. Turn on Bedrock invocation logging. Build a CloudWatch dashboard with endpoint latency and errors, plus Bedrock token counts, and add an alarm on output tokens per hour.
3. Re-run a training job with spot and checkpoints, and compare billable seconds with training seconds.
4. Write a least-privilege app policy and test it in the IAM Policy Simulator. Cause one `AccessDenied` and fix it using CloudTrail.
5. Run a training job in a private VPC with an S3 gateway endpoint and `enable_network_isolation=True`. Delete the interface endpoints the same day.
6. Add a contextual grounding check to a guardrail, attach it to knowledge-base queries, and test with an answerable question, an unanswerable one and a prompt injection hidden in a document.

### Self-check

1. Live input distributions drift from the training data. What detects this automatically?
2. Bedrock spend doubled while traffic stayed flat. What do you check first?
3. Training must not reach the internet at all. How?
4. Which service scans container images in ECR for vulnerabilities?
5. Who deleted the production endpoint last night? Where do you look?
6. Cheapest way to run steady, 24/7 SageMaker inference for a year?

**Answers.** 1: Model Monitor data-quality monitoring against a baseline. 2: Input and output tokens per request in CloudWatch: longer prompts, more chunks or more agent steps. 3: VPC mode with private subnets and no NAT, plus network isolation. 4: Amazon Inspector. 5: CloudTrail. 6: A right-sized instance (Graviton or Inferentia where possible) with a SageMaker Savings Plan.
