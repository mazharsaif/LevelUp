## 12. MLOps pipelines and CI/CD

This skill covers MLA-C02 Task 3.3: automating training, testing and deployment, managing model, prompt and agent versions, and retraining models and refreshing knowledge bases safely.

### SageMaker Pipelines

A pipeline is a directed graph of steps defined in Python, run on demand, on a schedule or from an event. Step types:

| Step | Does |
|---|---|
| Processing | Feature engineering, evaluation scripts |
| Training / Tuning | Train or tune a model |
| Model / RegisterModel | Create a model or add a version to the Model Registry |
| Condition | Branch on a metric (for example AUC ≥ 0.8) |
| Transform | Batch scoring |
| Lambda / Callback | Call out to other systems or wait for them |
| Fail | Stop with an error message |
| QualityCheck / ClarifyCheck | Compare data or bias against a baseline |

Pipelines cache unchanged steps, take parameters (for example instance type and thresholds), and record lineage from data to model.

### Model versions

- **SageMaker Model Registry**: model groups hold versions with metrics, lineage and an approval status (`PendingManualApproval`, `Approved`, `Rejected`). An approval can trigger deployment through EventBridge.
- **MLflow on SageMaker AI**: experiment tracking plus a model registry, for teams that already use MLflow.
- **Bedrock**: custom models have their own versions; **Prompt Management** versions prompts; **agents** have versions and **aliases** (point an alias at a version to roll forward or back).

### Deployment strategies

SageMaker **deployment guardrails** for updating endpoints:

- **Blue/green** with **all at once**, **canary** (a small slice first) or **linear** (equal steps) traffic shifting, with a **baking period**.
- **Auto rollback** when a CloudWatch alarm fires (for example on 5XX errors or latency).
- **Rolling** updates for endpoints that use inference components.
- **Shadow** variants to test without user impact.

### CI/CD on AWS

| Service | Role |
|---|---|
| AWS CodeConnections | Connects GitHub, GitLab or Bitbucket repositories to AWS |
| AWS CodeCommit | AWS-hosted Git (still on the exam; closed to new customers) |
| AWS CodeBuild | Runs builds and tests in containers |
| AWS CodeDeploy | Deploys with blue/green or canary and rollback (EC2, Lambda, ECS) |
| AWS CodePipeline | Orchestrates source → build → test → deploy stages, with manual approvals |
| CloudFormation / CDK | Infrastructure as code for endpoints, roles and pipelines |

A typical MLOps flow has two pipelines. The **build pipeline** runs on a commit: unit tests, then SageMaker Pipeline training, then registration. The **deploy pipeline** runs when a model is approved: deploy to staging, run tests, wait for manual approval, then deploy to production with a canary.

### Testing strategies

- **Code**: unit tests for feature functions and integration tests for pipelines.
- **Data**: schema and quality checks before training.
- **Models**: a minimum metric threshold, comparison with the current production model, bias checks and load tests on the endpoint.
- **GenAI**: prompt regression tests (a fixed set of prompts with expected properties: valid JSON, required fields, refusals for unsafe asks), LLM-as-a-judge scoring, and Guardrails tests.
- **Agents**: tool-call tests and end-to-end task tests, run before each new agent version gets the alias.

### Orchestration and retraining

- **Amazon EventBridge** schedules or reacts to events (a new file in S3, a model approved, an alarm).
- **AWS Step Functions** orchestrates multi-service workflows with retries and branching.
- **Amazon MWAA** (managed Apache Airflow) suits teams that already use Airflow DAGs.
- **Retraining triggers**: a schedule, a Model Monitor drift alarm, new labelled data arriving, or a performance drop.
- **Knowledge base refresh**: an S3 event or a schedule triggers Lambda, which calls `StartIngestionJob`. Then run an evaluation of retrieval quality before relying on the new index.
- **Fine-tuned FM automation**: a pipeline creates the customisation job, evaluates the new model, registers its version and updates provisioned throughput or the alias.

### Lab: a pipeline and CI/CD (about $0.20)

1. Build a SageMaker pipeline: Processing (features) → Training (XGBoost) → Processing (evaluation, writing `evaluation.json`) → Condition (AUC ≥ 0.75) → RegisterModel into the group `mla-bank` with `PendingManualApproval`.
2. Run it twice with different `eta` values, compare the two versions in the registry and approve the better one.
3. Put the code in GitHub, connect it with CodeConnections, and create a CodePipeline whose CodeBuild stage runs `pytest`, a 10-prompt regression test against your Prompt Management prompt, and then starts the SageMaker pipeline.
4. Sketch the EventBridge rule that deploys on approval and the one that retrains on a drift alarm.

### Self-check

1. A model should be registered only if AUC ≥ 0.8. Which pipeline step?
2. Shift 10% of traffic to a new model and roll back automatically on errors. How?
3. Roll an agent back to its earlier behaviour quickly. How?
4. Connect a GitHub repository to CodePipeline. Which service?
5. New documents land in S3 nightly and the knowledge base must pick them up. Design it.

**Answers.** 1: A Condition step. 2: A blue/green deployment guardrail with canary traffic shifting and a CloudWatch alarm for auto rollback. 3: Point the alias back at the earlier agent version. 4: AWS CodeConnections. 5: An EventBridge schedule (or an S3 event) triggers Lambda, which calls `StartIngestionJob`, followed by a retrieval evaluation.
