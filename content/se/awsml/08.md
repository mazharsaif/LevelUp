## 8. Features, quality and bias

This skill covers MLA-C02 Tasks 1.2 and 1.3: transforming data, engineering features, preparing data for GenAI, and checking data quality and bias.

### Feature engineering techniques

| Technique | What it does | Typical use |
|---|---|---|
| Standardisation (z-score) | Mean 0, standard deviation 1 | Linear models, k-means, neural nets, SVMs |
| Normalisation (min-max) | Scale to 0–1 | Neural nets, distance-based models |
| Log transform | Squash long right tails | Income, prices, counts |
| Binning | Turn a number into ranges | Age groups; non-linear effects |
| One-hot encoding | One column per category | Nominal categories with few values |
| Label / ordinal encoding | Categories → integers | Ordered categories; tree models |
| Feature splitting | Break one field into parts | Date → day of week, month; address → city |
| Feature crossing | Combine features | Location × time of day |

Tree models (XGBoost, random forest) do not need scaling; distance-based and gradient-based models do.

### Cleaning data

- **Missing values**: drop rows only if there are few; otherwise impute with the mean, median, mode or a model, and consider a "was missing" flag.
- **Outliers**: detect them with the IQR rule, z-scores or Random Cut Forest. Then cap, transform or investigate them; never delete them blindly.
- **Duplicates**: remove them before splitting, or the same row can sit in both train and test.

### Tools for transforming data

- **SageMaker Data Wrangler** (inside SageMaker Canvas): visual data prep with 300+ transforms and a Data Quality and Insights report that flags target leakage, duplicates and imbalance. It exports to a processing job or pipeline.
- **AWS Glue DataBrew**: no-code cleaning and profiling for analysts.
- **AWS Glue** and **Spark on Amazon EMR**: code-based, large-scale transformation.
- **AWS Lambda** or **Managed Service for Apache Flink**: transform streaming records.
- **SageMaker Feature Store**: create feature groups, reuse features across teams, and run point-in-time-correct queries for training.

### Quality and labelling

- **AWS Glue Data Quality** checks rules written in DQDL (data quality definition language), for example `IsComplete "age"` or `ColumnValues "age" between 18 and 100`, and scores each run.
- **DataBrew profile jobs** show distributions, missing values and correlations.
- **SageMaker Ground Truth** labels data with human workers (your team, vendors or Mechanical Turk), plus active learning that auto-labels easy items.

### Bias in data

**SageMaker Clarify** pre-training bias metrics, computed on a **facet** (a sensitive attribute such as age or gender):

| Metric | Measures |
|---|---|
| Class Imbalance (CI) | Is one facet group under-represented? |
| Difference in Proportions of Labels (DPL) | Does one group get positive labels more often? |
| KL / JS divergence | How different are the label distributions? |

Mitigations: collect more data for under-represented groups, resample, augment, stratify the train/test split, shuffle, and remove proxy features.

**Class imbalance** (for example 0.5% fraud): use oversampling or SMOTE, undersampling, class weights, and metrics such as recall, precision, F1 and PR-AUC instead of accuracy. For images and text, add augmentation (flips and crops, or paraphrases).

### Preparing data for GenAI

- **Embeddings**: turn text and images into vectors with a model such as Amazon Titan Text Embeddings V2 or Titan Multimodal Embeddings. Use the same model for documents and queries.
- **Text pre-processing**: tokenisation, normalisation and domain-specific augmentation.
- **Chunking for RAG**: fixed-size chunks with overlap, hierarchical chunks (small chunks for search, the parent for context), semantic chunks (split on meaning), or structure-aware chunks by heading. Attach metadata such as source, date and section, so you can filter and cite.
- **Mask, redact and anonymise** PII with Amazon Comprehend, Macie findings or Glue transforms before data is used for training or indexing.
- **Fine-tuning data**: JSONL prompt–completion pairs that are validated (valid JSON, no empty fields, no PII, no duplicates, safe content). Continued pre-training uses unlabelled domain text. Distillation uses prompts that a teacher model answers.

### Self-check

1. Which model needs standardised inputs: k-means or XGBoost?
2. Fraud is 0.5% of rows. Name two fixes and the metric to watch.
3. Which tool lets analysts clean and profile data with no code?
4. A RAG answer is cut off mid-table. What do you change first?
5. Which Clarify metric shows that one group gets positive labels more often?

**Answers.** 1: k-means, because it is distance-based. 2: Oversampling or SMOTE, and class weights; watch recall, precision, F1 or PR-AUC, not accuracy. 3: AWS Glue DataBrew. 4: The chunking, to structure-aware chunks with overlap so tables stay whole. 5: DPL (difference in proportions of labels).
