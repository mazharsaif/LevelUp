## 7. Data ingestion and storage

This skill covers MLA-C02 Task 1.1, part of Domain 1 (28%, the largest domain). The exam asks you to pick where data lives, which format to use, and how to bring in batch and streaming data.

### Where the data lives

| Service | Best for | Watch out for |
|---|---|---|
| Amazon S3 | The data lake: training data, model artefacts, any file | Not a database; use formats that support partitions |
| Amazon EBS | Block storage attached to one instance | Tied to one Availability Zone |
| Amazon EFS | Shared file system for many instances | Costs more than S3 per GB |
| Amazon FSx for Lustre | Very fast file access for large training jobs | Extra cost; use it when S3 reads are the bottleneck |
| Amazon RDS / Aurora | Relational, transactional data | Export to S3 before large-scale training |
| Amazon DynamoDB | Key-value lookups at any scale | Not built for analytical scans |
| Amazon Redshift | Data warehouse, SQL analytics | Charged while the cluster runs (or per use with Serverless) |
| Amazon OpenSearch Service | Search, logs and vector search | Serverless collections have a monthly cost floor |

Choose by cost, performance, data structure and compliance. Keep raw data in S3, transform it into a curated copy, and keep both.

### File formats

| Format | Type | Use it when |
|---|---|---|
| CSV | Row, text | Small data; SageMaker built-in algorithms (label first, no header) |
| JSON / JSON Lines | Row, text | Nested data, logs, Bedrock fine-tuning datasets |
| Apache Parquet | Columnar, compressed | Analytics that read a few columns; Athena, Glue, Spark |
| Apache ORC | Columnar, compressed | Hive and EMR workloads |
| RecordIO-protobuf | Binary | Fast streaming into some SageMaker built-in algorithms |

Columnar formats plus partitioning (for example by date) cut the bytes a query scans, and Athena charges per byte scanned.

### Moving and merging data

- **AWS Glue**: serverless Spark ETL, crawlers that infer schemas, and the **Data Catalog** that Athena, EMR and Redshift Spectrum share.
- **Amazon EMR**: managed Spark, Hive and Presto clusters for large or custom processing.
- **Amazon Athena**: serverless SQL straight on S3.
- **AWS DataSync**: copies on-premises or other storage into AWS.
- **AWS Lake Formation**: fine-grained permissions on a data lake.

### Streaming ingestion

| Service | What it does | Pick it when |
|---|---|---|
| Kinesis Data Streams | Durable stream of records in shards, replayable | You write custom consumers or need replay |
| Amazon Data Firehose | Fully managed delivery to S3, Redshift, OpenSearch; buffers, converts to Parquet, optional Lambda transform | "Near real time to S3 with no code to manage" |
| Managed Service for Apache Flink | Stateful stream processing (windows, joins) | Real-time aggregations and features |
| Amazon MSK | Managed Apache Kafka | You already use Kafka |

### Data for AI applications

- **Vector databases** store embeddings for semantic search and RAG: OpenSearch Service (k-NN, hybrid search), Aurora PostgreSQL or RDS with **pgvector**, **Amazon S3 Vectors** (lowest cost, no cluster), Neptune Analytics (graph RAG). Choose on scale, latency, cost and whether you need hybrid keyword-plus-vector search.
- **Multimodal data** (text, images, audio) usually sits in S3, with metadata in a table or catalogue.
- **SageMaker Feature Store** holds curated features. Ingest with `PutRecord`, the SageMaker Python SDK `ingest()`, or Spark. The online store serves the latest values in milliseconds; the offline store keeps history in S3.

### Troubleshooting ingestion

- Kinesis throttling (`ProvisionedThroughputExceededException`): add shards, use on-demand mode, or spread the partition keys.
- Slow training reads from S3: use Pipe or Fast File mode, shard files to 100 MB–1 GB, or use FSx for Lustre.
- Many tiny files slow Athena and Spark: compact them into bigger Parquet files.

### Lab: formats, a lake and a stream (about $0.15)

1. Create a bucket `mla-study-<initials>-euc1`. Upload the UCI Bank Marketing CSV to `raw/`. Convert it locally to Parquet (snappy) with pandas and upload it to `curated/`.
2. Create Athena tables over both and run `SELECT job, avg(balance) … GROUP BY job`. Compare the bytes scanned.
3. Run a Glue crawler on `curated/`, then a small Glue Spark job (G.1X, 2 workers, 10-minute timeout) that joins a `regions.csv` lookup and writes Parquet partitioned by region.
4. Create a Kinesis data stream with one provisioned shard and a Lambda consumer that writes clean JSON to S3. Send 200 records with boto3, then delete the stream.

### Self-check

1. Analysts read 3 of 120 columns from 2 TB of CSV every day. What is the biggest cost cut?
2. Clickstream must land in S3 within a minute, with no servers to manage. Which service?
3. Which vector store has no idle cost floor for a small knowledge base?
4. Features must be identical in training and inference and served in milliseconds. Where do they live?
5. What does a Glue crawler produce?

**Answers.** 1: Convert to partitioned Parquet. 2: Amazon Data Firehose. 3: Amazon S3 Vectors. 4: SageMaker Feature Store, in the online store for serving and the offline store for training. 5: Table definitions (schemas) in the Glue Data Catalog.
